Remediation Guide: PHP Lab and Apache2 Permissions

Review the vulnerabilities deployed under /var/www/html/, compare vulnerable and corrected PHP code, and apply the Linux and Apache2 permission fixes.

Match the examples to your installed lab

This guide uses ping_tool.php, visor.php, and upload.php with the upload field avatar. The repository's instalador_de_laboratorio_php_vulnerable.sh creates ping-tool.php, visor-logs.php, and subir-archivo.php, with the upload field archivo. Apply fixes to those installed files and update example URLs and field names consistently. Keep diario.txt and the report parameter archivo unchanged. The separate instservices script assigns 666 to its web files; these also need their write permissions corrected.

01

Phase 1: Fix filesystem permissions

The vulnerable lab uses root:root ownership with 777 permissions (rwxrwxrwx). This allows Apache's www-data user to modify PHP source or create files in writable web directories.

Vulnerable state

These commands describe the insecure starting state; they are not remediation steps.

bash
# All users, including www-data, can read, write, and traverse these directories
chmod 777 /var/www/html
chmod 777 /var/www/html/*.php
chmod -R 777 /var/www/html/uploads /var/www/html/reportes

How to fix it

PHP source must not be writable by www-data. Only /var/www/html/uploads should allow group write access. Apache must separately prevent script execution in that directory.

bash
# 1. Assign root ownership and the www-data group to the web directory
sudo chown -R root:www-data /var/www/html

# 2. Directories: readable and traversable, writable only by root
sudo find /var/www/html -type d -exec chmod 755 {} \;

# 3. Files: readable by Apache, writable only by root
sudo find /var/www/html -type f -exec chmod 644 {} \;

# 4. Allow Apache to write only to the uploads directory
sudo chown -R root:www-data /var/www/html/uploads
sudo chmod 770 /var/www/html/uploads

These commands assume the lab directories exist. Read-only reports remain under root ownership. New files created by PHP will normally belong to www-data; that is acceptable inside the dedicated uploads directory. File mode 0640 removes executable bits but does not stop PHP interpretation over HTTP. Apply the Apache configuration in Challenge 3 as well.

02

Challenge 1: Command injection

Vulnerable code — ping_tool.php

The $_POST['ip'] value is concatenated directly into shell_exec(), allowing additional commands through ;, &&, or |.

php
<?php
$output = "";
if (isset($_POST['ip'])) {
    $target = $_POST['ip'];
    // VULNERABLE: direct concatenation into a shell command
    $output = shell_exec("ping -c 3 " . $target);
}
?>

Fixed code — /var/www/html/ping_tool.php

Validate the input as an IPv4 or IPv6 address with filter_var(), then quote the shell argument with escapeshellarg(). Reject non-string input before calling trim().

php
<?php
// CHALLENGE 1 FIXED: network diagnostics without command injection
$output = "";
if (isset($_POST['ip'])) {
    $target = is_string($_POST['ip']) ? trim($_POST['ip']) : '';

    // 1. Accept only a valid IP address
    if (filter_var($target, FILTER_VALIDATE_IP) !== false) {
        // 2. Quote the argument to prevent shell injection
        $safe_target = escapeshellarg($target);
        $output = shell_exec("ping -c 3 " . $safe_target);
    } else {
        $output = "Error: Invalid IP address format.";
    }
}
?>
<!DOCTYPE html>
<html lang="en">
<head><meta charset="utf-8"><title>Network Diagnostics</title></head>
<body>
    <h3>Check server connectivity</h3>
    <form method="POST">
        <label>IP address: <input type="text" name="ip" placeholder="8.8.8.8"></label>
        <button type="submit">Ping</button>
    </form>
    <pre><?php echo htmlspecialchars($output ?? '', ENT_QUOTES, 'UTF-8'); ?></pre>
</body>
</html>
03

Challenge 2: Path traversal / LFI

Vulnerable code — visor.php

The $_GET['archivo'] parameter is appended directly to the reports directory. A value such as ../../../../etc/passwd escapes /var/www/html/reportes/.

php
<?php
$content = "";
if (isset($_GET['archivo'])) {
    $file = $_GET['archivo'];
    // VULNERABLE: ../ can escape the intended directory
    $path = "/var/www/html/reportes/" . $file;
    if (file_exists($path)) {
        $content = file_get_contents($path);
    } else {
        $content = "Report not found.";
    }
}
?>

Fixed code — /var/www/html/visor.php

Use basename() to select a filename and realpath() to resolve it. Verify that the base directory exists and that the resolved file remains inside it, including after symbolic link resolution. The trailing directory separator prevents a sibling path from matching the prefix.

php
<?php
// CHALLENGE 2 FIXED: report viewer protected against path traversal
$content = "";
$base_directory = realpath("/var/www/html/reportes");

if (isset($_GET['archivo'])) {
    $target_path = false;
    if ($base_directory !== false && is_string($_GET['archivo'])) {
        $clean_name = basename($_GET['archivo']);
        $target_path = realpath($base_directory . DIRECTORY_SEPARATOR . $clean_name);
    }

    if ($target_path !== false
        && strpos($target_path, $base_directory . DIRECTORY_SEPARATOR) === 0
        && is_file($target_path)
        && is_readable($target_path)) {
        $content = file_get_contents($target_path);
        if ($content === false) {
            $content = "Unable to read the report.";
        }
    } else {
        http_response_code(403);
        $content = "Access denied or report not found.";
    }
}
?>
<!DOCTYPE html>
<html lang="en">
<head><meta charset="utf-8"><title>Report Viewer</title></head>
<body>
    <h3>View a system report</h3>
    <a href="?archivo=diario.txt">View the daily report</a>
    <pre><?php echo htmlspecialchars($content, ENT_QUOTES, 'UTF-8'); ?></pre>
</body>
</html>

Fixed code — /var/www/html/download.php

Apply the same directory boundary check to downloads. Use an encoded filename in the response header so that an untrusted filename cannot introduce header syntax.

php
<?php
// FIXED: downloads limited to /var/www/html/reportes
$base_directory = realpath("/var/www/html/reportes");

if (isset($_GET['file'])) {
    $target_path = false;
    if ($base_directory !== false && is_string($_GET['file'])) {
        $clean_name = basename($_GET['file']);
        $target_path = realpath($base_directory . DIRECTORY_SEPARATOR . $clean_name);
    }

    if ($target_path !== false
        && strpos($target_path, $base_directory . DIRECTORY_SEPARATOR) === 0
        && is_file($target_path)
        && is_readable($target_path)) {
        header('Content-Type: application/octet-stream');
        header("Content-Disposition: attachment; filename=\"report\"; filename*=UTF-8''"
            . rawurlencode($clean_name));
        readfile($target_path);
        exit;
    }

    http_response_code(403);
    echo "Access denied or file not found.";
} else {
    echo "Usage: download.php?file=diario.txt";
}
?>

Keep the report directory and its files unwritable by Apache. The same containment check applies to path-traversal.php; preserve the parameter names used by that script.

04

Challenge 3: Arbitrary file uploads

Vulnerable code — upload.php

Trusting $_FILES['avatar']['name'] without checking the content allows a PHP script to be uploaded into /var/www/html/uploads/.

php
<?php
$message = "";
if (isset($_FILES['avatar'])) {
    $destination = "uploads/" . $_FILES['avatar']['name'];
    // VULNERABLE: no extension or content-type validation
    if (move_uploaded_file($_FILES['avatar']['tmp_name'], $destination)) {
        $message = "File uploaded to: " . htmlspecialchars($destination);
    }
}
?>

Fixed code — /var/www/html/upload.php

  1. Allow only jpg, jpeg, png, and gif, with a matching detected MIME type.
  2. Inspect the file with finfo_file() and getimagesize() and require a successful upload.
  3. Generate a random filename instead of retaining user-controlled names such as shell.php.jpg.

Image checks do not guarantee the absence of embedded PHP. The Apache execution block below remains required.

php
<?php
// CHALLENGE 3 FIXED: accept verified image uploads only
$message = "";
if (isset($_FILES['avatar'])) {
    $file = $_FILES['avatar'];
    if (!is_array($file)
        || ($file['error'] ?? null) !== UPLOAD_ERR_OK
        || !is_string($file['tmp_name'] ?? null)
        || !is_string($file['name'] ?? null)
        || !is_uploaded_file($file['tmp_name'])) {
        http_response_code(400);
        $message = "Upload failed or invalid upload request.";
    } else {
        $tmp_name = $file['tmp_name'];
        $extension = strtolower(pathinfo($file['name'], PATHINFO_EXTENSION));

        // 1. Match each allowed extension to its expected MIME type
        $allowed_types = [
            'jpg' => 'image/jpeg',
            'jpeg' => 'image/jpeg',
            'png' => 'image/png',
            'gif' => 'image/gif',
        ];

        // 2. Inspect the actual file content
        $finfo = finfo_open(FILEINFO_MIME_TYPE);
        $actual_mime = $finfo !== false ? finfo_file($finfo, $tmp_name) : false;
        if ($finfo !== false) {
            finfo_close($finfo);
        }

        // 3. Check for recognizable image dimensions
        $image_info = @getimagesize($tmp_name);

        if (isset($allowed_types[$extension])
            && $actual_mime === $allowed_types[$extension]
            && $image_info !== false
            && ($image_info['mime'] ?? '') === $actual_mime) {
            // 4. Replace the user-supplied filename with a random name
            $new_name = bin2hex(random_bytes(16)) . "." . $extension;
            $destination = "/var/www/html/uploads/" . $new_name;

            if (move_uploaded_file($tmp_name, $destination)) {
                // Restrict filesystem access; Apache blocks PHP interpretation separately
                if (chmod($destination, 0640)) {
                    $message = "Image uploaded as: " . $new_name;
                } else {
                    unlink($destination);
                    http_response_code(500);
                    $message = "Unable to apply file permissions.";
                }
            } else {
                http_response_code(500);
                $message = "Unable to save the image.";
            }
        } else {
            http_response_code(400);
            $message = "Blocked: Only valid JPG, PNG, and GIF images are allowed.";
        }
    }
}
?>
<!DOCTYPE html>
<html lang="en">
<head><meta charset="utf-8"><title>Upload Avatar</title></head>
<body>
    <h3>Upload a profile image</h3>
    <form method="POST" enctype="multipart/form-data">
        <input type="file" name="avatar" accept="image/jpeg,image/png,image/gif">
        <button type="submit">Upload Image</button>
    </form>
    <p><?php echo htmlspecialchars($message, ENT_QUOTES, 'UTF-8'); ?></p>
</body>
</html>

Block script execution in /uploads/ through Apache2

Place the following block in /etc/apache2/sites-available/000-default.conf inside the applicable virtual host. Apply it to the HTTPS virtual host too if the lab uses one. A <Directory> block cannot be placed in .htaccess; keeping the policy in root-owned server configuration also prevents the writable uploads directory from overriding it.

This image-only policy denies other file types, disables directory listing and CGI, and forces allowed images through the static file handler. The conditional PHP directive adds protection when using mod_php. Existing PHP files should return 403, rather than expose their source as plain text.

apache
<Directory "/var/www/html/uploads">
    AllowOverride None
    Options -ExecCGI -Indexes -Includes -FollowSymLinks -SymLinksIfOwnerMatch
    AcceptPathInfo Off

    <IfModule php_module>
        php_admin_flag engine off
    </IfModule>

    <FilesMatch "(?i)\.(jpe?g|png|gif)$">
        SetHandler default-handler
        Require all granted
    </FilesMatch>
    <FilesMatch "(?i)^(?!.*\.(jpe?g|png|gif)$).*$">
        Require all denied
    </FilesMatch>
</Directory>

Check Apache's configuration before reloading:

bash
sudo apache2ctl configtest && sudo systemctl reload apache2

The policy assumes these uploads are public images. Verify it against the active virtual host and PHP handler configuration, especially if other rules override handlers. See the Apache Directory documentation and SetHandler documentation.

05

Challenge 4: Fix patterns in cloned scripts

Apply these patterns to basic-collection.php, path-traversal.php, and the additional GitHub lab examples, using the actual input names and database API in each file.

1. Cross-site scripting (XSS)

Vulnerable:

php
echo "Hello " . $_GET['name'];

Fixed for HTML text and quoted HTML attributes:

php
$name = is_string($_GET['name'] ?? null) ? $_GET['name'] : '';
echo "Hello " . htmlspecialchars($name, ENT_QUOTES, 'UTF-8');

Other output contexts, such as JavaScript or URLs, require context-appropriate handling.

2. SQL injection (PDO / MySQLi)

Vulnerable:

php
$id = $_GET['id'];
$result = $db->query("SELECT * FROM users WHERE id = '$id'");

Fixed using PDO prepared statements:

php
$id = filter_input(INPUT_GET, 'id', FILTER_VALIDATE_INT);
if ($id === false || $id === null) {
    http_response_code(400);
    exit('Invalid user ID.');
}
$stmt = $db->prepare("SELECT * FROM users WHERE id = :id");
$stmt->execute([':id' => $id]);
$result = $stmt->fetchAll();

This example assumes $db is a PDO connection and IDs are integers. MySQLi uses its own prepare() and bind_param() API rather than PDO named placeholders.

3. Disable dangerous functions in php.ini (optional)

If no scored service needs to execute system commands from PHP, edit the active Apache PHP configuration under /etc/php/<version>/apache2/php.ini:

ini
disable_functions = exec,passthru,shell_exec,system,proc_open,popen,pcntl_exec
expose_php = Off
allow_url_fopen = Off
allow_url_include = Off

If the validator or scorebot requires real ping functionality, keep shell_exec enabled and apply the Challenge 1 code fix. Disabling URL file access may also affect legitimate integrations. With PHP-FPM, use the active FPM configuration and reload the matching FPM service.

The lab's /etc/php/<version>/apache2/conf.d/99-ccdc-misconfig.ini explicitly enables expose_php and error display. Remove those conflicting overrides or update that file too; a change in php.ini alone can be overridden by files loaded afterward. Reload the active PHP runtime after changes.

06

Post-patch verification commands

Run these checks after applying the fixes to confirm that legitimate functionality remains available and the attack inputs are rejected. Replace the example IP with your lab server's address.

bash
export ipphpserver="192.168.1.100"

# 1. Legitimate ping works (SLA OK); command injection is rejected
curl -s -X POST "http://$ipphpserver/ping_tool.php" -d "ip=8.8.8.8" | grep "bytes from"
curl -s -X POST "http://$ipphpserver/ping_tool.php" -d "ip=127.0.0.1; id"

# 2. The daily report opens (SLA OK); traversal cannot read /etc/passwd
curl -s "http://$ipphpserver/visor.php?archivo=diario.txt"
curl -s "http://$ipphpserver/visor.php?archivo=../../../../etc/passwd"

# 3. PHP file uploads are rejected
echo '<?php system("id"); ?>' > test_shell.php
curl -s -F "avatar=@test_shell.php" "http://$ipphpserver/upload.php"

Use a reachable IP permitted by the isolated lab network if 8.8.8.8 is unavailable. A failed external ping alone does not establish whether injection is fixed. The viewer should show the daily report, and the traversal request should return an access-denied response without system file contents.

Also test a real image upload and confirm that Apache blocks an existing PHP test file in the uploads directory:

bash
# Replace avatar.png with a real, local image
curl -sS -F "avatar=@avatar.png" "http://$ipphpserver/upload.php"

# On the Apache server: create an inert PHP execution marker
printf '%s\n' '<?php echo "UPLOAD_EXECUTION_MARKER"; ?>' | sudo tee /var/www/html/uploads/execution-check.php >/dev/null
sudo chmod 644 /var/www/html/uploads/execution-check.php

# On the administration machine: expect 403, with no execution marker or PHP source
curl -i "http://$ipphpserver/uploads/execution-check.php"

Fetch the generated image URL returned by a successful upload to confirm it is served. Run the marker setup commands on the server and the HTTP request on the administration machine where $ipphpserver is set. Restore the disposable lab snapshot after completing the exercise.
